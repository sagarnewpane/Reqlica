# Database setup

Use a draft's `database/schema.json` to declare new SQLite tables. Setup is
additive: existing table changes need [migrations](maintenance.md).

## Workflow

1. Save the schema plan with handlers and tests in the draft.
2. Open **Drafts & checks → Database setup → Preview schema**.
3. Review the compiled SQL, then validate and test the draft. Checks apply the
   plan to disposable data before loading handlers.
4. Choose **Apply to live database…** and confirm the current checked revision.
5. Review, approve, and activate the code separately.

Live application rechecks schema and preview digests, saves a backup, and creates
missing tables in one transaction. It persists even if you never activate code.
After an uncertain response, preview again before retrying.

## Plan format

```json
{
  "version": 1,
  "tables": [
    {
      "name": "books",
      "columns": [
        { "name": "id", "type": "INTEGER", "primary_key": true },
        { "name": "title", "type": "TEXT", "nullable": false }
      ]
    }
  ]
}
```

Types: `INTEGER`, `TEXT`, `REAL`, `BLOB`, `NUMERIC`. Names start with a letter and
contain letters, digits, or underscores, up to 63 characters. Integer primary
keys can be generated by SQLite. `default` accepts scalar literals, not SQL
expressions. Columns support `unique` and `references`; tables support
`unique_together`. `SET NULL` references require nullable columns.

Limits: 64 KiB, 20 tables, 50 columns per table. Preserve earlier declarations and
append tables. Existing declared tables must match the compiled SQL exactly;
do not remove/re-add declarations to imitate alteration.

## API

Prefix: `/api/projects/{project_id}/drafts/{draft_id}/database`.

- `POST /preview`: `{expected_revision}`; returns SQL, pending tables,
  `schema_fingerprint`, and `preview_digest`.
- `POST /apply`: `{expected_revision, expected_schema, expected_preview_digest,
confirm: true}`; requires passing checks and a current draft base.

Backups live in `.reqlica/database-backups/` and are not automatically pruned.
Table creation does not implement authentication or supply signing keys;
configure private values through [environment settings](environment.md).
